The test of every phase

Can a skeptical customer use the evidence to make a decision?

Software skill is necessary. FDE readiness comes from translating uncertainty into a scoped plan, a safe system, a compelling demonstration, and an adoption path.

Default to one sturdy workflow with a clear evaluation before building an autonomous agent or complex platform.

Portfolio-grade FDE builds

Five industry projects
that prove judgment.

Build these as customer-style deployments, not generic chatbots. Every project needs a baseline, an integration, an evaluation set, safety controls, a business metric, and a live executive demo.

Build orderStart with support or logistics. Use regulated projects once you can show access control, audit trails, evaluation and human approval.
01

Financial services

Compliance investigation desk

Turns policy, case files and transaction notes into a cited analyst brief—never an automatic risk decision.
Impact to prove

Reduce analyst research time, improve evidence completeness, and make every claim traceable to an approved source.

Tech stack

Python, FastAPI, PostgreSQL + pgvector, Azure OpenAI or Bedrock, LangGraph, hybrid retrieval, RAGAS, Langfuse, Docker, Terraform.

Build it
  1. Ingest policies and cases with role-based access.
  2. Build hybrid retrieval, reranking and citations.
  3. Connect a mock case system through a narrow tool.
  4. Add a reviewer approval queue and audit log.
  5. Red-team prompt injection and evaluate every answer.
02

SaaS and enterprise support

Case resolution orchestrator

Classifies support tickets, finds grounded answers, drafts replies and proposes safe actions for an agent to approve.
Impact to prove

Lower time to resolution, first-response time and escalation rate without letting the model close high-risk cases alone.

Tech stack

FastAPI, OpenAI Agents SDK or LangGraph, Zendesk/Salesforce mock APIs, OAuth, PostgreSQL, Redis, MCP, LangSmith, GitHub Actions, Docker Compose.

Build it
  1. Model ticket, customer and entitlement data.
  2. Retrieve product docs with source citations.
  3. Classify intent and route to deterministic flows.
  4. Require approval before any external update.
  5. Track resolution, correction and handoff metrics.
03

Logistics and operations

Shipment exception control tower

Explains late or at-risk shipments, surfaces the operational reason, and coordinates an approved recovery workflow.
Impact to prove

Improve on-time recovery, reduce manual exception triage and protect SLA-sensitive orders with earlier intervention.

Tech stack

Python, FastAPI, PostgreSQL, Kafka or Redpanda, Redis, LangGraph, OpenAI or Claude API, Grafana, OpenTelemetry, Docker, Kubernetes.

Build it
  1. Stream simulated tracking events and carrier updates.
  2. Make consumers idempotent and model SLA timers.
  3. Explain exception reasons from events and playbooks.
  4. Draft a recovery plan with a human approval step.
  5. Load-test bursts and demonstrate graceful degradation.
04

Manufacturing and industrial AI

Maintenance intelligence workbench

Combines sensor patterns, maintenance manuals and parts data to help technicians prepare—not to autonomously control equipment.
Impact to prove

Reduce diagnosis time, avoid repeated work orders and improve planned-maintenance readiness while keeping a technician in control.

Tech stack

Databricks, PySpark, Delta Lake, Unity Catalog, FastAPI, Qdrant or pgvector, Claude or OpenAI API, Langfuse, Grafana, Docker.

Build it
  1. Create a governed sensor and work-order data model.
  2. Detect simple anomalies with transparent rules.
  3. Retrieve manuals, safety steps and parts constraints.
  4. Generate a cited technician checklist.
  5. Measure usefulness with technician-style test scenarios.
05

Healthcare administration

Referral and document intake triage

Extracts and validates referral information, routes incomplete packets, and prepares a human review queue. It does not diagnose or recommend treatment.
Impact to prove

Reduce intake turnaround, missing-document rework and manual data entry while preserving privacy, auditability and escalation paths.

Tech stack

FastAPI, OCR or Document AI, PostgreSQL, Azure OpenAI or Bedrock, Pydantic, RBAC/OIDC, Presidio-style PII controls, Phoenix, Docker, Terraform.

Build it
  1. Define a safe administrative scope and data flow.
  2. Extract structured fields with validation and confidence.
  3. Mask PII in evaluation data and logs.
  4. Route uncertain or incomplete records to reviewers.
  5. Produce a HIPAA/DPDP-style security and rollback brief.

Deep research scan

What exists. What is still missing.

There is no single elite "FDE degree." The strongest preparation is a deliberately assembled intersection of software, ML systems, human-centered product work, and client delivery.

Convergent signals across roles and curricula

The FDE competency model

Current FDE postings ask for end-to-end ownership.

OpenAI emphasizes discovery, scoping, system design, build, rollout, adoption, and field feedback. Scale emphasizes Python or TypeScript, robust backend/data integrations, cloud, containers, Linux, networking and customer delivery.

A React-first curriculum is not the role signal.

Some FDE jobs are full-stack and React can be a bonus or a client-stack requirement; it is not a universal FDE core. The durable skill is a thin, trustworthy operational interface or a precise integration contract—not marketing-site frontend work.

Top systems courses prioritize reliability over notebook fluency.

Stanford's ML systems path includes data, deployment, monitoring, privacy, fairness, security, and the human side of ML. MIT teaches fault tolerance, replication, and consistency. CMU goes deep on data systems and recovery.

The bootcamp scans strengthen several core modules.

Your materials emphasize local and open-weight inference, synthetic data, retrieval selection, evals, guardrails, agent memory, harness engineering, fine-tuning and voice. Those are now explicit in this fieldbook, placed after backend/data foundations and before production delivery.

Adjacent titles matter.

Anthropic commonly uses Applied AI Engineer or Architect; Palantir uses Forward Deployed Software Engineer. Search by the work—customer-facing technical delivery—not only the title.

Curriculum decision

Spend your time where hiring signals overlap.

Prioritize

Full-stack product craft, API and data integration, systems trade-offs, evals, security, concise writing, discovery, business cases, adoption.

Learn, then use selectively

RAG, agents, vector search, workflow orchestration, Kubernetes, fine-tuning, GraphRAG. They are tools, not the role.

Do not confuse with readiness

Framework collecting, prompt tricks, multi-agent demos, and algorithm drills without an operating or customer context.

Framework and library atlas

The complete working stack

This is the selection map for the tools you will encounter. It is intentionally broad, but it tells you what to master, what to choose between, and what to recognize in a customer environment.

Coverage rule

Master the capability; choose the framework for the constraint.

You do not become FDE-ready by memorizing every package. You become ready when you can select a small, compatible stack, explain the trade-offs, integrate it safely, and leave a client with an operable system. The atlas covers the modern FDE surface area so no major layer is invisible.

Build deepUse routinely, debug independently, and prove in a shipped project.
Select wellKnow decision criteria and use one representative tool end to end.
RecognizeUnderstand purpose, risks, integration points, and when to bring a specialist.

01 · Core engineering

Foundations and quality

The non-negotiable baseline for every client environment.

Build deepPython, TypeScript, SQL, Bash, Git, Linux, HTTP, JSON, networking, concurrency and debugging.
Select welluv or Poetry, npm or pnpm, Ruff or Black, ESLint, Prettier, Make, Docker dev environments.
Verify withpytest, Vitest or Jest, Playwright, Testcontainers, k6 or Locust, Postman or Bruno.

02 · Delivery surface

Operational interfaces and demos

FDEs make workflows usable. They do not need to become dedicated frontend engineers.

Build deepGradio, Streamlit, notebooks, CLI workflows, basic HTML/CSS and trustworthy states for operators.
Select wellExisting customer UI, low-code tools or a small custom interface; use React or Next.js only when the integration needs it.
AI deliveryServer-Sent Events, WebSockets, citations, review states, recovery paths and Sentry; explain the contract to the client UI team.

03 · Services

Backend, APIs and contracts

Expose capabilities that an enterprise can reliably call and govern.

Build deepFastAPI, Pydantic, SQLAlchemy, Alembic, REST, OpenAPI, auth, background processing and error design.
Select wellExpress or NestJS, GraphQL, gRPC, Uvicorn, Nginx, API gateways, webhooks, SSE and WebSockets.
Durable workCelery, RQ, Dramatiq, Temporal and Inngest; choose from execution guarantees, not fashion.

04 · Information plane

Data, integration and analytics

Most FDE work succeeds or fails at the seams between systems.

Build deepPostgreSQL, Redis, schema design, migrations, query plans, data quality and source-of-truth decisions.
Select wellMongoDB, DuckDB, S3 or GCS or Blob Storage, Kafka or Redpanda, webhooks, ETL and CDC.
At scaledbt, Airbyte or Fivetran, Spark, Databricks, Airflow, Prefect, Dagster and lakehouse governance.

05 · Model plane

LLMs, routing and serving

Choose models from requirements, observed quality, cost and data boundaries.

Build deepOpenAI, Anthropic, Gemini APIs; prompting, structured output, tool calling, context limits and model evaluation.
Select wellAmazon Bedrock, Azure OpenAI, Google Vertex AI, LiteLLM, model routing, batching and caching.
Private servingOllama, vLLM, Hugging Face TGI, quantization, GPU capacity, latency and privacy trade-offs.

06 · Knowledge plane

RAG and document intelligence

Ground model output in authorized evidence with proof of retrieval quality.

Build deepChunking, metadata, ACL-aware retrieval, citations, hybrid search, reranking, abstention and RAG evaluation.
Select wellLangChain, LlamaIndex, Haystack, Unstructured, Docling, Apache Tika, OCR and document parsing.
Vector layerpgvector, Qdrant, Pinecone, Weaviate, Milvus, FAISS; embedding and reranking model families.

07 · Agent plane

Agents, workflows and protocols

Favor controlled stateful workflows; add autonomy only where it earns its cost.

Build deepTool schemas, state machines, checkpoints, approvals, retries, budgets, permissions and human escalation.
Select wellOpenAI Agents SDK, LangGraph, PydanticAI, Semantic Kernel, AutoGen and CrewAI.
InteroperateMCP servers and clients, A2A, OAuth for tools, Temporal or Inngest, event-driven workflow patterns.

08 · Evidence plane

Evals, tracing and operations

Make quality, cost and failures observable before rollout.

Build deepTask datasets, scoring rubrics, regression testing, error taxonomies, release gates and outcome metrics.
Select wellRagas, DeepEval, Promptfoo, Braintrust, OpenAI Evals, LangSmith, Langfuse and Phoenix.
Operate withOpenTelemetry, Prometheus, Grafana, Sentry, Datadog, logs, traces, metrics, alerts and runbooks.

09 · Production guardrails

Cloud, security and compliance

Design for enterprise trust, not merely a successful demo.

Build deepDocker, Compose, IAM, secrets, OAuth2, OIDC, JWT, RBAC, threat modeling and data residency.
Select wellKubernetes, Helm, Terraform or OpenTofu, Pulumi, GitHub Actions, Argo CD, Cloud Run, ECS and Azure Container Apps.
Harden withSAML, SCIM, Vault or OpenBao, OPA, Presidio, Semgrep, dependency scanning, SOC 2 and OWASP GenAI Top 10.

10 · Customer plane

Discovery, business and adoption

The part no library can replace—and the reason a deployment survives.

Build deepDiscovery interviews, active listening, stakeholder maps, requirements, system storytelling, demos and concise written updates.
Select wellMECE, 5 Whys, jobs-to-be-done, RICE, MoSCoW, architecture decision records, risk registers and SOWs.
Drive adoptionROI and KPI models, training, champions, feedback loops, Notion, Linear or Jira, Slack, Loom, Miro, Figma and 30/60/90-day plans.

Hiring readiness standard

A curriculum can create evidence. It cannot guarantee an offer.

Hiring depends on the market, location, work authorization, interview performance and the role’s seniority. This fieldbook therefore uses a hard evidence gate: complete it only when your work shows the judgment and technical delivery the role needs—not merely when every lesson is watched.

Three deployment proofsThree scoped customer-style systems with a backend, data integration, evals, security posture and an adoption plan.
One deep capstoneA live deployment with a discovery document, ROI or KPI, system design, red-team report, traces and an operator handoff.
Interview evidenceThree timed ambiguous cases, five ownership stories, practical Python/SQL/API debugging and a 20-minute design defense.
Targeted applicationsA portfolio, resume and company thesis tailored to the FDE, FDSE, Applied AI Engineer and AI Deployment Engineer role families.
